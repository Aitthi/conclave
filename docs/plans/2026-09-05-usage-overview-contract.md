## Settled measurement and presentation
One durable model_usage_event relation stores measured response/usage records; no logical-turn/attempt pair in this feature. Add durable model_usage_coverage state. Armin correctly identified that an event-only table cannot distinguish no events from no observation (challenge d325d8c2 on usage-contract-review). Coverage must retain observed intervals/gaps per source and scope; a single first-seen timestamp is insufficient to claim continuous observation after outages. Interrupted, unsupported and unvalidated intervals are unknown. No provider billing/cost model, raw prompt/output storage, or summing context snapshots.

Overview shows recorded model activity and measured token usage for the same filters and range, grouped by model, agent and workspace. Requested model never impersonates served model: show Unknown model when unobserved. Current context remains a separate latest gauge with source and observation time; it is not a period total. Archived workspace history is included by default and labelled Archived. Hidden internal scratch workspaces are excluded from normal workspace lists; unscoped operations must not be silently assigned to the selected workspace.

Default period: last 90 calendar dates including today in the browser's IANA timezone. Offer 30 and 90 days initially. Buckets are calendar dates, half-open UTC intervals calculated using that timezone (DST-aware). Heatmap uses seven weekday rows and chronological week columns, month/date labels, count legend and keyboard/focus details for every cell. Outside-range cells are blank, not zero. Current day is in progress. Keyboard navigation and an accessible daily table provide exact date/count/coverage values. All model, workspace and agent filters apply equally to metrics, breakdowns and heatmap. Provider names may be shown as model metadata; no independent provider filter is required initially.

Coverage states: complete, partial, none. A fully observed empty interval may display 0. No coverage displays unavailable; partial empty intervals display an em dash, not 0. Partial intervals with observed events display their recorded count with a partial marker. Known token subtotal is labelled Measured tokens and paired with the number of activity records whose token usage is unknown; it is never presented as total account consumption. Before collection starts, historical buckets remain unknown. A chart can truthfully show measured records on partial coverage without manufacturing missing history.

## Durable event invariants
Each event has immutable local id and UNIQUE versioned source-namespaced event_key; workspace, optional workspace-agent/session and generation captured at collection; source_kind/collector version; source occurred_at and recorded_at; provider, requested_model and nullable served_model; normalized nullable input_tokens and output_tokens; optional cache read/write breakdown; explicit token completeness/provenance. No persisted synthetic total_tokens. Display input+output only when both are known; aggregate known subtotals with missing counts.

Normalized input_tokens includes all input tokens, including cached input. Cache read/write are subsets and must NOT be added again. Claude normalization may add its disjoint uncached/cache-create/cache-read components only when source semantics establish them; OpenAI prompt_tokens already includes cached tokens. Missing usage is NULL, not automatically zero. Exact per-source mappings require verified source evidence and tests before enabling collection.

Only verified completed responses or verified stable usage records enter activity. Failed/cancelled provider operations do not count as completed activity. Direct provider collection requires a terminal result carrying model/usage; receiver loss or premature transport EOF is not success. Dedup is stable across replay and restart. Transcript collector cursor advancement and event upserts share a transaction; preserve bounded incremental scanning and strict workspace/owner/generation attribution. Do not enable Codex from the current last_token_usage reduction. The dedicated evidence task determines whether its richer source format is importable; until then it is unknown, not permanently excluded.
