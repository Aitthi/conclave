# Self-triggered restart becomes an in-place context reset (handoff → /clear → resume)
owner: 30fa04f4-e047-4241-a9ed-f452529952be · authority: in-loop
Implementer: Tiësto (e60b9644-28b2-4a3f-a9d3-229ad50d5d47), allocated by Detoro. Reviewer: Mellow (b3a30e7b-5a9f-4d4d-a83e-768a9326632f). Detoro rules and merges. Start lane from main at or after 242f9f0.

## Why now
Human request 2026-10-01 (verbatim intent): "แก้ระบบ restart หลัง context meter เกิน 70% — ไม่ต้อง restart shell จริงๆ แค่ handoff → ส่ง /clear → รอสักพัก → ค่อยส่งให้อ่าน last snapshot". Today the self-triggered path (ADR 0006, `conclave restart`) arms a save-gated tail that KILLS the PTY process, respawns it, waits 8 s for boot, then injects the resume prompt (`src-tauri/src/engine/commands/instance.rs` `run_respawn_resume_state`). Killing the process costs a full CLI boot, drops the shell/browser/MCP state, and flips the UI through idle → running for nothing: the harness's own `/clear` already produces a fresh context while the system-prompt layer (identity preamble, skill-file pointer) survives it (`src-tauri/src/engine/agentctx.rs` lines 1-12).

## Rulings (final — challenge on the task if the code contradicts them)
R1. **Scope = the self-triggered path only.** `conclave restart` (ADR 0006, `self_triggered: true`) switches to clear-in-place. The human-triggered Restart · resume button (`ContextBars.tsx`, `self_triggered: false`) and the not-live respawn path keep the kill → respawn → resume tail byte-for-byte. Reason: the button's label and its "saving"/"respawning" phases promise a relaunch, and a human may use it on a hung process.
R2. **Command name stays `conclave restart`.** The strategic-compact skill, the 70 %/85 % nudges in `task_timer.rs`, agent memories and `skill.rs`'s test all name it; renaming buys nothing. Its semantics change, its docs change.
R3. **The arm carries a mode.** `AppState.restart_pending` stores `(Instant, RestartMode)`; `RestartMode::{Respawn, ClearInPlace}`. `take_restart_pending` returns `Option<RestartMode>`. Same TTL, same consume-once.
R4. **Clear command per `cli_kind`:** `claude-code` → `/clear`; `codex` → `/new`. Any other kind (none shipped today; opencode / muse are planned) → fall back to the existing respawn tail (`run_respawn_resume_state(.., kill_first = true)`) and `eprintln!` why. Pure fn `clear_command_for(cli_kind: &str) -> Option<&'static str>` in `instance.rs`, unit-tested.
R5. **Timing:** after the save lands, sleep `RESTART_SETTLE_MS` (existing 2 000 ms, lets the agent's "saved" line render), submit the clear command, sleep new `CLEAR_SETTLE_MS: u64 = 3_000`, then submit `resume_restore_prompt()`. Both submits go through `super::snapshot::submit_line` (bracketed paste + `\r`), the same seam every injected prompt already uses. Re-check `state.runtime.is_live` before each submit; if the agent died in between, return silently (mirror the boot-settle check at instance.rs ~2278).
R6. **No process kill, no status flip.** The clear tail must NOT call `runtime.unregister`, must NOT set status idle, must NOT emit SESSION_STATUS. Call `runtime::browser::mark_resumed(&instance_id)` once after the clear is submitted — the agent loses its browser context exactly as it does on respawn, so the browser first-commit gate must re-arm the same way.
R7. **Prompt wording.** `self_restart_instruction` (agentctx.rs ~187) replaces "The restart (kill, respawn, resume) fires automatically once your save lands — after it confirms, stop and wait." with: "Once your save lands the context reset fires automatically: Conclave sends /clear (codex: /new) into your own terminal, waits a few seconds, then sends you the resume prompt — your process is NOT killed. After the save confirms, stop and wait; do not type anything." Keep the re-arm sentence. `resume_restore_prompt` (agentctx.rs ~204): replace "Your process was restarted and this is a fresh context." with "Your context was reset (in-place /clear or a process restart) and this is a fresh context." Everything after that sentence is unchanged. `restart_save_prompt` (human path) and its frozen-baseline test stay byte-identical (R1).
R8. **Standing rule text** (`src-tauri/skills/strategic-compact/SKILL.md`, section "Don't wait for a forced compact"): say that `conclave restart` no longer kills the process — it arms an in-place reset (handoff saved → `/clear` typed into your terminal → resume prompt), and that the agent must stop typing after `conclave snapshot save` confirms. The literal `conclave restart` must remain (skill.rs test ~1372).
R9. **Record:** new `docs/adr/0009-inplace-context-reset.md` (status: accepted) — supersedes ADR 0006's "process killed → fresh terminal spawned" bullet for the self-triggered path; states R1, R4, R5 and the rejected alternative (keep killing: costs boot + state; respawn with `--resume`: rejected again for the reasons in ADR 0006). Add a one-line "Superseded in part by ADR 0009" note at the top of ADR 0006 — do not rewrite it.

## Risk ledger
- Codex `/new` meter: `transcript_context::poll_codex` keys the meter on the newest rollout file; `/new` starts a new rollout so the meter should collapse and re-arm the 70 % nudge (`CONTEXT_NUDGE_REARM_RATIO`). Verify by reading `poll_codex` (~173) and note the conclusion; if the meter would NOT collapse, say so in the READY note — it is a follow-up, not a blocker.
- The 3 s clear settle is a guess at Claude Code's SessionStart hook latency (it runs `owner_marker_command`). If the resume prompt lands while the hook is still running, the TUI queues it — acceptable. Make the constant easy to bump; do not add config.
- `mark_resumed` touches a process-global registry — use the real instance id, never a literal, in tests.
- Shared-tree hazard does not apply (own worktree), but commit with `git commit -- <paths>` anyway and `git show --stat` before posting the SHA.
